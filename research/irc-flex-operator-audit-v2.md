# IRC Flex numerical and operator audit v2

2026-09-07. DRAFT_FROM_EVIDENCE. Reader decision: whether a new backend warrants actual-weight qualification. This is not a methods result or a SOTA claim.

## Decision

Native BF16 Flex passes all nine decode cells but fails the supplemental causal prefill check: 30230/4227072 output elements violate the predeclared pointwise tolerance. The exact mask and finite/zero-output checks pass. This native backend is not admitted from these results.

Paired controls use the same BF16 query, key, value and mask hashes. Default SDPA fails 30909 elements; SDPA MATH and native Flex with lossless FP32 inputs and a BF16 output cast each have zero violations. All retain the original FP64 oracle and rtol0.005/atol0.0005. A raw precision option first caused a compiler error; the retained retry uses the public highest-precision setting. The observations support precision sensitivity, not a uniquely isolated error mechanism or universal equivalence.

These findings motivate the separate `fp32_prefill_flex` candidate in `irc-mixed-precision-runtime-protocol-v3.md`. It casts only query-length-greater-than-one attention inputs, registers both native interfaces and keeps the original cache/scorer/workload. Native BF16 v2 remains failed. Actual model output, replay and full-budget checks decide v3 admission; native backward is a later unpassed dependency.
