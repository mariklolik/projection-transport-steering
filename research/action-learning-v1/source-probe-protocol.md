# Fit-only SGLang source-collection qualification v1

Engineering protocol, frozen before new model outputs on 2026-09-08. This does not authorize the four-arm learning experiment or change any closed experiment.

## Discovery before code

The existing `irc_baseline_support.checked_packet` validates the frozen allocation, eligibility, uniqueness and content hash. `outcome_score_runtime.rollout_seed` provides question/rollout-addressed seeds. The original Qwen tokenizer and instruction are already available locally, with tokenizer JSON and config hashes matching baseline-v3. Reuse these to prepare a token-only request packet on CPU; do not import the old intervention/attention/grade stack into the newer SGLang image. Existing native generation is an intervention runtime, not a drop-in batched SGLang collector. Existing author extraction/equivalence and `score_math_outputs` remain the grading authority after collection; no new grader.

New code is limited to preparing the frozen requests, joining SGLang outputs by explicit request ID with strict raw-token/termination checks, and running the bounded engine probe. The caller contract is one raw record per requested question/rollout, preserving input/output token IDs, seed, complete engine metadata, and EOS. Reordering must not alter row identity; missing, duplicate, unknown, aborted, silently trimmed or inconsistent outputs fail closed. No strings are re-tokenized to reconstruct targets, and caps are not admitted as complete preference traces.

## Frozen scope and sampling

- First eight questions in the already frozen fit allocation order, four rollouts each. Allocation file SHA256 `2585bc810dc0089f342a1e578f37f4372f9c103090be0bba1932c56fdca6e4eb`. The original 1500 fit questions remain unchanged. No response, selection, development or sealed data is accessed by the probe.
- Qwen/Qwen3-8B snapshot `b968826d9c46dd6066d109eabc6255188de91218`; same native user instruction and chat template as baseline-v3, thinking enabled. Inputs are prepared by the hash-checked local tokenizer and passed as token IDs. SGLang skips tokenizer initialization; decode/scoring happens separately using the original tokenizer and grader.
- Seeds reuse `rollout_seed(cluster_id, rollout_index)`, indices 0–3, and are stored per request. Sampling: temperature 0.6, top-p 0.95, top-k 20, max-new-tokens 8192, explicit stop IDs 151643/151645, ignore-EOS false, no-stop-trim true. No penalties, grammar, speculative decoding, LoRA, or intervention. This is a newly versioned source policy, not assumed bitwise identical to the historical native sampler.
- Stages in order: one warmup request from the first fit question, capped at 16 solely for warmup and excluded from source/quality; one batch of all 32 requests; one batch repeating the first four requests in reverse order; two single-request calls repeating the first two requests. Repeats keep the original per-request seed. Thus 38 full-cap completions, 32 unique source requests, eight unique questions, plus one warmup. No outcome-based subset changes or retries.
- Check repeat token equality and reason equality against the main batch, both under reordering and batch-size changes. A mismatch blocks reproducibility admission but does not erase the raw measurement. Native-versus-SGLang output equality is not a gate or a promised property.

## Measurements and gates

Persist configuration, request packet and source hashes before launch; exact model metadata and shard identity/size/hash evidence; runtime versions; GPU UUID and occupancy; raw outputs immediately after each completed stage; engine settings/logs; stage wall seconds and token counts; sampled process memory/GPU utilization; inclusive container lifetime. Report prompt/output lengths, EOS/cap counts, completion coverage, batch throughput and all stage timings. Eight reused questions and only one main batch do not support population uncertainty or a serving-speedup claim against the different historical population. Repeats are engineering checks, not independent quality observations.

PASS requires exact hashes/runtime, all expected joins, valid raw-token/EOS-or-cap contracts, no abort/OOM/retraction, and identical repeated token sequences/reasons. A length cap is recorded, not a complete training target. The grade/pair-yield summary is descriptive fit-only evidence; this tiny deterministic prefix cannot establish corpus-wide pair yield or quality. Any malformed output or missing stage fails the probe. Failure never triggers cap relaxation or removal of affected rows.

The next decision uses measured startup and source-length scenarios, with separate full-length backward/reference memory and four-fit/evaluation reserves. Full 1500×4 collection and four-arm training remain unadmitted until total resource feasibility and the exact scientific protocol pass. SOTA, protected retention, mechanisms, three-family/three-construct transfer and paper prose gates remain unpassed.
