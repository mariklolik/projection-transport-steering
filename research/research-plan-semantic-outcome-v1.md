# Semantic-outcome research plan, version 1

Freeze date: 2026-09-07. Status: active successor plan after the independent fail-closed closure of InvariantBack and powered CacheBack.

## Decision

Version 20, InvariantBack, and powered CacheBack remain closed under their original gates. No product-cap change, certificate relaxation, verbalizer repair, dataset deletion, common-dose reinterpretation, or joint branding is permitted. CacheBack's local mechanism result remains supported at its recorded scope.

The next independent route changes the behavioral object: it constructs a concept action from matched multi-token semantic outcomes and requires local progress for every construction witness. The working candidate is `SemanticOutcomeBack`; the name is not manuscript-authorized before evidence.

## Evidence-first sequence

1. Freeze nearest work, mathematical claim, AxBench frontier, sources, estimands, splits, uncertainty, resource limits, and stop rules.
2. Add only the missing diagonal robust-action adapter and deterministic tests.
3. Materialize and hash the exact 2B model, Concept16k, FLAS checkpoint, and environment on FSK before any forward pass.
4. Run one sentinel concept on one currently idle H100.
5. If smoke passes, shard 12 exposed concepts across currently idle GPUs with one model replica and at most two CPU threads per worker.
6. Analyze the immutable packet deeply before opening the 24-concept development allocation.
7. Open the 64-concept internal pilot only after the frozen development gate and official-judge receipt pass.
8. Open the 100 held-out concepts, then 9B, only after the preceding gate. Add a Qwen-family transfer study only after both Gemma frontier cells pass.
9. Re-run claim, A-star, and research-strength audits. Paper prose remains closed until evidence is fair-strong.

## Faster GPU funnel

| Stage | GPU allocation | Maximum exposed science | Stop condition |
|---|---:|---:|---|
| Algebra | 0 | Synthetic systems only | Any deterministic invariant fails |
| Smoke | 1 | 1 sentinel concept | Replay, gradient, KKT, serialization, or memory failure |
| Sentinel | Up to 8 idle GPUs | 12 concepts, tuning prompts only | Any frozen SO.1-SO.4 or coverage gate fails |
| Development | Up to 8 idle GPUs | 24 new concepts, tuning prompts only | Adjusted HMean, retention, stratum, or Pareto gate fails |
| Internal pilot | Up to 8 idle GPUs | 64 new held-in concepts | Fair-strong input-matched receipt fails |
| Frontier | Up to 8 idle GPUs | 100 held-out concepts per admitted model | SOTA or family gate fails |

The scheduler rechecks process ownership, memory, utilization, and free memory immediately before launch. It never uses a busy GPU, limits CPU and interop threads per worker, loads each model once per shard, batches positive and negative continuations where shapes allow, and prepares/validates CPU packets while GPU shards run. A model failure is written atomically and does not abort unrelated concepts; it still counts against coverage.

## Deeper analysis contract

Every stage reports coverage and missingness before effects; concept-level paired distributions rather than only means; BCa intervals where powered; worst-witness and mean-witness results; active-constraint counts and dual concentration; witness-gradient agreement; exact action and metric costs; neutral likelihood and tokenwise KL; concept, baseline-score, length, disagreement, cost, and boundary-factor strata; severe individual generations; pass, backward-product, wall, memory, and token counts; and Pareto plots retaining behavior, collateral, and compute separately.

The analysis must distinguish construction fit, held-out teacher-forced mechanism, tuning-prompt open generation, official test behavior, and published-frontier comparison. None can be substituted for another.
